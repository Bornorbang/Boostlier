# Contact support

`/dashboard/support` is linked directly after API, separated by a horizontal rule. The page uses native keyboard-accessible accordions, with inline query forms for wallet payments and Boost Account. The wallet-payment form contains a disabled account email and required receipt upload (PDF/JPEG/PNG/WebP, maximum 5 MB), without a message field. Boost delay guidance explains the 24?72 hour timeframe. The API accordion is removed and the centered footer reads ?Still have a query? Please email support@boostlier.com?. SMS guidance is informational only and explains cancellation, wallet refunds and trying another number. Additional informational answers cover wallet withdrawals and platform acceptance.

Forms submit authenticated JSON to the existing `/support` backend route. The account identity comes from the session, not editable customer input. Queries require an allowed issue, a 10–2,000 character description, an optional reference of at most 255 characters and an idempotency key. The same payload/key returns the same ticket; altered reuse is rejected. A one-minute per-account cooldown and ten attempts per hour limit submission abuse. Developer API keys do not expose support endpoints.

Tickets remain in the existing `support_tickets` table and administrator support list. Wallet receipt submissions require a validated private attachment; other queries do not require one. Admin receipt download is shown only where a receipt exists. Legacy multipart receipt submissions remain supported by the existing backend route and legacy delivery process.

Migration 024 adds ticket retry keys and an optional support ticket link on the transactional mail queue. Ticket insertion and one queued email occur in the same transaction. The existing dedicated mail worker delivers new queries to `SUPPORT_EMAIL` (configured as support@boostlier.com), using the authenticated sender and the customer's account email as Reply-To. The subject identifies the issue without a ticket ID. The body includes only submitted fields: email plus the attached receipt for payment uploads, or email, any supplied reference and message for other queries. Internal customer/ticket IDs, account name, timestamps and automatic receipt descriptions are omitted. HTML is escaped. Provider failures back off and retry for up to seven days; pending ticket state remains visible to administrators. SMTP delivery is at least once: a process crash after acceptance but before status persistence can resend an email, while the support ticket itself remains unique. The general jobs runner excludes these tickets from its legacy support loop to avoid duplicate delivery paths.

The mail worker was reloaded locally. Production must keep it supervised as documented in ACCOUNT-EMAIL.md. No existing support-ticket backlog was drained as part of this change.

Seven review passes: sidebar/route placement, FAQ and form accessibility, backend validation/ownership, retry/cooldown behavior, SMTP routing and Reply-To, administrator compatibility, desktop/mobile and regression verification. Ten support unit tests, twelve account-mail tests, twenty-one admin regressions, browser integration, TypeScript/static checks and production build passed. A clearly labelled isolated support test was accepted by the configured SMTP server; inbox placement is not independently confirmed.

Run `php backend/tests/support-queries.php` and `node tests/support-queries-browser.mjs` for the isolated test paths. They do not send customer emails. Service/API documentation remains limited to purchasable service endpoints.

Receipt multipart submissions use the same owner/session identity, idempotency and queue logic. File content MIME and image headers are validated server-side; files are stored under generated names outside the public web root. Receipt content hashes bind retry keys to the original upload. SMTP delivers receipts as actual attachments and admin retains authenticated download access. Production PHP must allow `upload_max_filesize=5M` and `post_max_size=6M` or higher; the local PHP server now uses these limits.
